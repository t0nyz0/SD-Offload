# SD Offload QA — September 26, 2026

Scope: source review, automated regression and transfer-safety checks, release-build performance baseline, and native UI inspection. Initial QA covered 1.7.9; subsequent tag editing, viewer hints, and AI-provider work are included in release 1.7.12. The local app was updated and restarted on 1.7.12. Initial verification results below describe that phase; follow-up results are recorded at the end.

## Assessment

The transfer safety checks passed. The Library had concrete responsiveness and clarity problems, now addressed in this change. This is not a certification of sustained physical SD-card/SMB performance or every hardware failure mode.

## Fixes

| Area | Finding | Change |
| --- | --- | --- |
| UI responsiveness | Volume-name getters, volume statistics, initial NAS folder lookup, and fallback search metadata could perform filesystem work on the main actor. | Move these reads to background work; guard asynchronous publication against navigation changes. |
| Navigation | An older browse could replace the current folder's contents. | Cancel obsolete requests and use a request generation to reject late results. Regression test deliberately completes the old folder late. |
| Counts and errors | Failed enumeration could be saved as a complete zero count. The installed UI displayed 0 items above populated folders. | Distinguish successful, failed, and cancelled counts; do not persist failed totals; recheck legacy zero totals. The original live zero's exact historical cause was not established. |
| Background I/O | Detached folder work did not inherit cancellation; cancelled queued metadata requests still read files. | Forward cancellation into recursive workers and skip cancelled metadata reads. An already-blocked filesystem syscall remains non-interruptible. |
| Viewer memory | Eight cached full-resolution images had no byte budget; rapid paging could overlap full decodes. | Add a 384 MiB retained-image budget and one-at-a-time full-image decoding. This is a cache budget, not a whole-process memory limit. |
| Default NAS browsing | High thumbnail quality reads full non-RAW images over the network. | Default to Balanced; preserve explicit quality preferences. |
| Idle work | The waiting-for-card illustration updated at 20 Hz while visible. | Use a static illustration. |
| Favorites | Temporarily unavailable favorites were pruned from saved state. | Keep saved paths when files are unavailable; regression test covers offline favorites. |
| Ratings | Highest-rated sorting did not update immediately after rating a photo. | Rebuild the sorted display after rating changes. |
| Discoverability | Search competed with all controls in one row; filtered-empty states looked like empty folders. | Separate search and action rows; explain active filters, failed loads, AI analysis, and search coverage. |
| Accessibility | Covered grid controls remained exposed behind the viewer; rating stars were announced as Favorite. | Hide the covered grid, name rating actions, and expose an open action for folder tiles. |
| Visual accuracy | Viewer background showed the underlying grid; PNG/HEIC photos were labeled JPEG. | Opaque viewer backdrop and extension-based photo format labels. |
| Destructive controls | Deleting all face data had no confirmation. | Explain exactly what is removed and require confirmation. |
| Erasure messaging | Idle copy promised that inserting a card clears it regardless of configuration. | Explain that Card & Offload settings govern copying and erasure. |

## Initial QA verification

- `swift test`: **113 tests passed, zero failures**. Seven new regressions cover enumeration failure/cancellation, nested media counts, cancellation propagation, byte-budget eviction, offline favorites, unavailable-library count persistence, and navigation/rating behavior.
- `bash Scripts/harness.sh`: **all ten modes passed**: normal transfer, NAS failure, unreadable file, crash/resume, wrong card, second copy, failed second destination, second-copy resume, missing final destination, and corrupted final destination. The harness used temporary directories because disk-image attachment was unavailable. No real card was erased.
- `swift build -c release`: passed.
- Native UI inspection: live installed popover and NAS Library; isolated release demo popover, folder grid, viewer, keyboard paging, Escape/back navigation, filter menu and filtered-empty message, and all five Settings categories. The final viewer accessibility tree excludes the covered Library controls and correctly announces rating actions and PNG format.
- The demo used 24 local image fixtures, its own bundle identifier, and a disposable data root. No cloud AI call, library migration, or real-photo deletion was exercised.

## Performance measurements

Release command: `swift run -c release offload-harness benchmark`.

Fixture: 256 MiB synthetic local file, copy with inline SHA-256 and fsync, followed by an uncached read-back hash. Three sequential trials; all hashes matched.

| Metric | Results |
| --- | --- |
| Copy + hash throughput | 1,318 / 1,303 / 1,163 MiB/s |
| Uncached verify throughput | 2,343 / 2,321 / 2,311 MiB/s |
| Combined copy + verify | 0.304 / 0.307 / 0.331 seconds |
| Browse and sort 2,000 local files | 0.026 seconds |

These are filesystem microbenchmarks, not the complete journaled offload pipeline and not SD-card or SMB benchmarks. They establish a reproducible baseline, not a before/after speedup claim.

Process samples: installed app with a folder view had an 87.5 MB physical footprint, 164.4 MB peak. An intermediate QA build after thumbnail loading and viewer paging had a 547.7 MB footprint, 610.4 MB peak. Different data and UI states make these **non-comparable**; they do not demonstrate a memory reduction. Cache bounds are covered by a deterministic eviction test. Whole-process memory remains a profiling priority.

## Remaining hardware validation and follow-ups

1. Measure sustained end-to-end transfer throughput on the actual SD reader and NAS, including simultaneous Library scrolling, reconnect, pause/resume, and final verification. Do not trade away read-back verification for speed.
2. Profile 10,000–100,000-photo libraries with large RAW/JPEG files: time to first thumbnails, scroll frame times, peak memory, and cancellation backlog. Local 2,000-entry enumeration is not sufficient to sign off large SMB libraries.
3. Audit remaining synchronous startup/index loads and card-root probing under slow or unavailable storage. The fixes remove specific confirmed main-actor reads, not every filesystem operation in the app.
4. Review ordering of detached favorites/culling/folder-stat persistence. Atomic writes prevent partial JSON, but rapid concurrent snapshots can still be written out of order. This session did not redesign persistence.
5. Complete a VoiceOver-only and keyboard-only photo-selection pass, reduced-motion/contrast testing, and light-appearance verification. Folder and viewer accessibility improved, but a full accessibility certification was not performed.
6. Exercise real video codecs, optional Claude providers, login items, notifications, and migration on disposable media in their intended environments. Existing migration/decoder tests passed; external integrations were not invoked during this QA.

Suggested performance acceptance targets for the next hardware run (targets, not measured results): warm navigation under 100 ms, UI response under 100 ms during transfer, no sustained main-thread disk/network waits, and no unbounded memory growth during repeated viewer paging.

## Reproduce isolated UI QA

Use a separate QA app bundle and set `OFFLOAD_DEMO=1`, `OFFLOAD_DEMO_IDLE=1`, and an absolute `OFFLOAD_DEMO_DATA_ROOT` pointing to disposable fixtures. Put a config JSON there with `nasRootPath` targeting the fixture library. Omitting idle mode runs the scripted fake transfer. Never test wipe behavior against real mounted cards.
